1. The mental model

Two axes decide where a file lives: which site the problem came from, then which language you solved it in. That is the whole layout.

/home/othman/work/problemSolving
├── leetcode/          problems from leetcode.com
│   ├── typescript/
│   ├── bash/
│   ├── php/
│   └── lua/
├── codewars/          problems from codewars.com
├── etc/               anything else
├── templates/         starter files used by `mask new`
├── lib/php/test.php   the check() helper PHP solutions use
├── maskfile.md        every task: new, run, test, lint, check, fmt
├── tsconfig.json      TypeScript settings for `bun check`
└── package.json       Bun types + scripts

So a LeetCode two-sum in TypeScript is leetcode/typescript/two-sum.test.ts, in PHP is leetcode/php/two-sum.php, and in Lua is leetcode/lua/two-sum.tl. Migrating a solution to another language never changes its platform folder.

The name is the slug: lowercase, words joined by hyphens, matching the problem URL. two-sum, sum-of-digits, fizz-buzz. No CamelCase, no underscores, no spaces.

Every problem file (solution and test) begins with the title and the link, so you can jump back to the statement without searching:

// Problem: Two Sum
// Link: https://leetcode.com/problems/two-sum/

The Bash and PHP templates use # comments instead of //. The scaffold writes these headers for you; you should never need to type one by hand.

2. The 60-second loop

The loop you will repeat for every problem:

  1. Scaffold: mask new <platform> <language> <slug> <url>
  2. Implement the solution and write real test cases.
  3. Run just that solution: mask run <platform> <language> <slug>
  4. Before committing: mask check (all tests + lint).

Formatting is a separate, safe-to-run-at-any-time step: mask fmt.

A concrete run for LeetCode's Two Sum in TypeScript:

mask new leetcode typescript two-sum https://leetcode.com/problems/two-sum/
# created leetcode/typescript/two-sum.test.ts
# run:     bun test leetcode/typescript/two-sum.test.ts

mask run leetcode typescript two-sum

3. Scaffolding with mask new

mask new <platform> <language> <slug> <url> [title]
ArgumentAccepted values
platformleetcode, codewars, etc
languagets/typescript, bash/sh, php, lua/tl/teal
slugkebab-case file name, e.g. two-sum (validated)
urlmust start with http:// or https:// (validated)
titleoptional; defaults to the slug title-cased (two-sum → “Two Sum”)

What gets created, per language:

LanguageFile(s) createdTest runner
TS<platform>/typescript/<slug>.test.tsBun
Bash<slug>.sh + <slug>.batsbats
PHP<platform>/php/<slug>.phpthe file itself
Lua<platform>/lua/<slug>.tltl run

Under the hood the task copies templates/<language>, substitutes {{TITLE}}, {{URL}}, {{SLUG}} and {{PLATFORM}}, then refuses to overwrite anything that already exists. Pass --force (or -f) when you really want to replace a file:

mask new --force leetcode typescript two-sum https://leetcode.com/problems/two-sum/
The function name is derived from the slug: camelCase for TypeScript and Lua (two-sum → twoSum), snake_case for PHP (two-sum → two_sum), as-is for Bash (two-sum). A leading digit gets an underscore prefix.
If mask new stops with “already exists”, that is the guard working. Either pick a new slug or add --force deliberately — do not delete files by hand to get around it.

4. Running one problem

mask run picks the right runner and file for you:

mask run leetcode typescript two-sum   # bun test leetcode/typescript/two-sum.test.ts
mask run leetcode bash two-sum         # bats      leetcode/bash/two-sum.bats
mask run leetcode php two-sum          # php       leetcode/php/two-sum.php
mask run leetcode lua two-sum          # tl run    leetcode/lua/two-sum.tl

The raw commands are worth knowing when you want to pass extra flags:

LanguageDirect command
TSbun test leetcode/typescript/two-sum.test.ts
Bashbats leetcode/bash/two-sum.bats
Bashbash leetcode/bash/two-sum.sh (manual demo only)
PHPphp leetcode/php/two-sum.php
Luatl run leetcode/lua/two-sum.tl

Submission-ready JavaScript

Some sites only accept JavaScript. Do not maintain a second copy: write and test the TypeScript file, then strip it on demand.

mask strip leetcode/typescript/two-sum.test.ts
# prints plain JavaScript, ready to paste

The task removes the bun:test import and every describe(...) block, erases types with esbuild, drops export modifiers, then prints the result (esbuild must be in PATH). So this TypeScript…

import { describe, expect, test } from "bun:test";

export function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>();
  // ...
  return [];
}

describe("Two Sum", () => {
  test("example 1", () => {
    expect(twoSum([2, 7, 11, 15], 9)).toEqual([0, 1]);
  });
});

…becomes this JavaScript:

function twoSum(nums, target) {
  const seen = new Map();
  // ...
  return [];
}

Write to a file instead of stdout with -o. A bare file name works when it is unique (mask strip two-sum.test.ts); if the same slug exists under two platforms, pass the full path.

mask strip -o /tmp/two-sum.js leetcode/typescript/two-sum.test.ts
The TypeScript file is the source of truth. Never fix a bug in a hand-copied JS file — fix the TS, run its tests, then strip again.

5. Testing

mask test runs all suites in one go:

mask test
# bun test              → every *.test.ts
# bats <all *.bats>     → bash behaviour
# tl check + tl run     → every *.tl

Tests live next to the solution. Only Bash uses a separate file; the other two keep tests in the same file as the answer.

TS Bun test in the same file

// Problem: Two Sum
// Link: https://leetcode.com/problems/two-sum/

import { describe, expect, test } from "bun:test";

export function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>();

  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    const j = seen.get(need);
    if (j !== undefined) return [j, i];
    seen.set(nums[i], i);
  }

  return [];
}

describe("Two Sum", () => {
  test("example 1", () => {
    expect(twoSum([2, 7, 11, 15], 9)).toEqual([0, 1]);
  });
});

The .test.ts suffix is what makes bun test discover the file with zero configuration.

Bash a sourceable solution + a bats file

The solution defines functions and nothing else. The guard at the bottom runs a demo only when you execute the file directly; sourcing it from the test file stays silent.

#!/usr/bin/env bash
# Problem: Two Sum
# Link: https://leetcode.com/problems/two-sum/

two_sum() {
  local target=${1}
  shift
  local -a nums=("$@")
  local -A seen=()

  for i in "${!nums[@]}"; do
    local need=$((target - nums[${i}]))
    if [[ -n ${seen[${need}]+x} ]]; then
      echo "${seen[${need}]} ${i}"
      return 0
    fi
    seen[${nums[${i}]}]=${i}
  done
}

# Runs only when executed, not when sourced by the .bats file.
if [[ ${BASH_SOURCE[0]} == "$0" ]]; then
  two_sum 9 2 7 11 15
fi
#!/usr/bin/env bats
# Problem: Two Sum
# Link: https://leetcode.com/problems/two-sum/

bats_load_library bats-support
bats_load_library bats-assert

setup() {
  source "${BATS_TEST_DIRNAME}/two-sum.sh"
}

@test "example 1" {
  run two_sum 9 2 7 11 15
  assert_success
  assert_output "0 1"
}

bats-assert gives you assert_success, assert_failure, assert_output, assert_line, refute_output and friends. bats-file is installed too, for problems that touch the filesystem (assert_file_exists, …).

Do not add sideways checks to the .sh file. If you want a check()-style assertion, write a bats @test instead — that is the whole point of the second file.

PHP assertions at the bottom

<?php
// Problem: Two Sum
// Link: https://leetcode.com/problems/two-sum/

declare(strict_types=1);

require_once __DIR__ . '/../../lib/php/test.php';

function two_sum(array $nums, int $target): array {
  $seen = [];

  foreach ($nums as $i => $n) {
    $need = $target - $n;
    if (isset($seen[$need])) {
      return [$seen[$need], $i];
    }
    $seen[$n] = $i;
  }

  return [];
}

check(two_sum([2, 7, 11, 15], 9), [0, 1], 'example 1');

check(actual, expected, label) exits non-zero on the first mismatch, so php file.php doubles as the test run.

6. Type checking with bun check

Bun 1.4 ships a builtin type checker. It reads tsconfig.json and checks the files under leetcode/, codewars/ and etc/:

bun check
# ✓ No type errors in 1 file

It fails the command on real type errors, so it is safe to use as a gate:

bun check
# <error file="etc/typescript/bad-type.ts" line="1" column="7" code="TS2322">
# Type 'string' is not assignable to type 'number'.
# Found 1 error in 1 file, checked 2 files
Never add a package.json script named check. Bun resolves scripts before builtin subcommands, so a "check" script silently shadows bun check and the type checker never runs. That is why the repo has "verify": "mask check" instead.

7. Lint & format

mask lint catches things tests do not:

StepToolCovers
bun checkBunTypeScript types
shellcheckShellCheckevery *.sh under the three platforms + lib/
php -lPHPsyntax of every *.php

mask fmt formats instead of complaining. It uses your own formatter scripts from PATH:

LanguageCommand usedNotes
TSbiome-checkruns biome check --fix
Bashshellfmt -i -fshfmt + ShellCheck fixes, per .sh file
PHPphpfmtphpcbf + php-cs-fixer, in place
LuaceruTeal formatter, in place
Two deliberate exceptions: .bats files are skipped by shellcheck/shellfmt (they are not plain shell syntax), and templates/ is formatted but not linted. Expect phpfmt to report unfixable docblock sniffs for small kata solutions — it still exits 0 and writes the file.
mask fmt      # may rewrite files — run it whenever, then re-run tests
mask lint     # read-only checks, no rewrites

8. mask check: the gate

mask check is the one command to trust before a commit. It runs, in order:

  1. $MASK test → bun test, bats, tl check + tl run
  2. $MASK lint → bun check, shellcheck, php -l
  3. prints all checks passed only if everything succeeded

It does not format. That is intentional: a check should never mutate the working tree. Run mask fmt separately (then mask check again if formatting changed code).

9. Language cheat sheets

TypeScript

  • File: <platform>/typescript/<slug>.test.ts
  • Template: templates/typescript.ts (one skipped example test)
  • Solve: export a function/class, write real test(...) cases in the describe, delete the test.skip
  • Run: mask run leetcode typescript two-sum or bun test path
  • Types: bun check

Bash

  • Files: <slug>.sh (functions) + <slug>.bats (tests)
  • Templates: templates/bash.sh and templates/bash.bats
  • Solve: implement the function; keep the BASH_SOURCE guard at the bottom
  • Test: setup() sources the .sh, each @test uses run + assert_output
  • Run: mask run leetcode bash two-sum or bats path.bats
  • Libraries: bats-support, bats-assert, bats-file

PHP

  • File: <platform>/php/<slug>.php
  • Template: templates/php.php, with declare(strict_types=1)
  • Solve: implement the function, then add check(actual, expected, 'label') lines at the bottom
  • Run: mask run leetcode php two-sum or php path.php
  • Helper: lib/php/test.php — exits 1 on the first mismatch

Lua

  • File: <platform>/lua/<slug>.tl (Teal source)
  • Template: templates/lua.tl
  • Solve: implement the function; assertions at the bottom run via tl run
  • Run: mask run leetcode lua two-sum or tl run path.tl
  • Types: tl check path.tl
  • Submit: mask strip path.tl compiles to Lua with tl gen

10. Rules & gotchas

RuleWhy
Header in every solution and test fileYou can open any file and know the problem; agents follow the same rule.
kebab-case slug = file namemask new validates it; keeps paths predictable.
One problem per file (Bash: one pair)Grep/jump by slug; no hidden shared state between problems.
Do not add a check script to package.jsonIt shadows bun check, disabling type checking.
Bash solutions only define functionsSourcing from bats must not execute tests or demos.
Let mask new create filesGuarantees the header, the right folder and the right suffixes.
Empty language folders stay via .gitkeepGit does not track directories; the structure stays visible.

Adding a brand-new platform (not just another LeetCode problem) is the one case the tooling does not automate. Create the language folders you use (or all of them, with a .gitkeep) and start scaffolding.

11. Walkthroughs

LeetCode problem in TypeScript

  1. mask new leetcode typescript valid-anagram https://leetcode.com/problems/valid-anagram/
  2. Implement isAnagram in the file.
  3. Replace test.skip with real cases from the statement.
  4. mask run leetcode typescript valid-anagram
  5. mask fmt && mask check

CodeWars kata in Bash

  1. mask new codewars bash sum-of-digits https://www.codewars.com/kata/541c8630095125aba6000c00
  2. Implement the function in sum-of-digits.sh; leave the guard alone.
  3. In sum-of-digits.bats, replace the skipped test with run + assert_output.
  4. mask run codewars bash sum-of-digits
  5. mask check

Problem in PHP

  1. mask new etc php reverse-string https://example.com/reverse-string
  2. Implement it in etc/php/reverse-string.php.
  3. Add check(...) lines for the examples and edge cases.
  4. mask run etc php reverse-string
  5. mask fmt, then mask check

Problem in Lua (Teal)

  1. mask new etc lua reverse-string https://example.com/reverse-string
  2. Implement it in etc/lua/reverse-string.tl.
  3. Add assert(...) lines (Lua uses 1-based indices).
  4. mask run etc lua reverse-string
  5. mask strip etc/lua/reverse-string.tl to get the compiled Lua

12. Troubleshooting

SymptomCause / fix
bun check runs mask check instead of type checking A "check" script in package.json shadows the builtin. Rename it ("verify") and run bun check again.
mask new: “already exists” Intentional guard. Use a different slug, or --force if you mean to overwrite.
bats: command not found Install bats; tests also need bats-assert and bats-support (both already present on this machine).
bats exits 0 but nothing ran Check the file ends in .bats and each case starts with @test "...".
ShellCheck complains about unbraced variables (SC2250) This setup prefers braces: ${var}, and indexes as ${arr[${i}]}. mask fmt does not fix every style warning.
bun check ignores a file Only leetcode/**, codewars/**, etc/** are in tsconfig.json’s include.
php -l passes but execution fails Expected: the template’s solve() throws until you implement it (and unused functions do not run).
tl not found Install the Teal toolchain (tl, ceru) via LuaRocks.
mask not found Install the task runner (already in PATH here) or invoke mask --maskfile maskfile.md <task>.

Before you commit:

  • Header present in every new file (solution and test).
  • Slug matches the problem URL and the file name.
  • Real assertions, not the template’s skip/todo/#[ignore].
  • mask fmt then mask check both finish cleanly.
